# Support & Issue Reporting

## Getting Help

### Report bugs & request features on GitHub

All bug reports and feature requests go here: **[github.com/joehomeskillet/Razzoozle/issues](https://github.com/joehomeskillet/Razzoozle/issues)**

The repository has templates for both bug reports and feature requests — GitHub will guide you when you create a new issue.

### Check the docs first

Before opening an issue, review the documentation:

- **[Self-Hosting Guide](docs/Self-Hosting.md)** — Docker setup, reverse proxy, beamer/kiosk configuration
- **[Configuration](docs/Configuration.md)** — game settings, quizzes, question types
- **[Theming](docs/Theming.md)** — the manager design cockpit, colors and presets
- **[Low-Latency Mode](docs/LOW-LATENCY-MODE.md)** — performance tuning for unreliable networks
- **[Full Documentation](docs/)** — all guides and references

## Writing a good bug report

When you file a bug, include:

1. **What happened** — a clear description of the unexpected behavior.
2. **Steps to reproduce**:
   - …
   - …
   - (be specific; "I clicked X, then Y happened" is better than "it doesn't work")
3. **What you expected** — what should have happened instead.
4. **Your environment**:
   - Docker or bare-metal
   - Browser and operating system
   - Razzoozle version (check the footer of the app, or the Docker image tag)
   - If self-hosted: any relevant settings from `config/game.json` or environment variables

5. **Screenshots or video** (if visual) — helps us reproduce faster.

Use the **Bug report** template when you create a new issue — it has these fields built in.

## Suggesting a feature

Good feature requests explain:

1. **The problem** — what is hard or missing today?
2. **Your idea** — what would you like to see?
3. **Alternatives** — anything else you've tried.

Use the **Feature request** template when you create a new issue.

## Questions & discussions

If you have a question about how to use Razzoozle (not a bug), consider:

- Re-reading the relevant doc above.
- Checking closed issues on GitHub for similar questions.
- Opening a new issue labeled `question` if you're still stuck — maintainers will help.
